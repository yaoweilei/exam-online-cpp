## 1. 评估口径

### 完成度口径

| 等级 | 含义 |
| --- | --- |
| `高` | 后端路由/服务存在，前端入口或调用链存在，当前版本可跑通主要链路 |
| `中` | 后端与部分前端存在，但缺少系统性回归、人工验收或仍有明显实现欠账 |
| `低` | 功能仅部分落地、默认关闭、前台隐藏、或更接近原型/占位 |
| `占位` | 前端有入口或文案，但后端闭环不足，不能视为正式完成 |

### 测试状态口径

| 状态 | 含义 |
| --- | --- |
| `已自动化验证` | 本轮执行过编译、`smoke_tests`、接口冒烟或现有回归脚本覆盖到主链路 |
| `部分自动化` | 仓库内有相关测试脚本或可间接覆盖，但本轮未逐项执行 |
| `未见自动化` | 当前未发现明确自动化覆盖，或覆盖面明显不足 |

### 人工确认口径

| 状态 | 含义 |
| --- | --- |
| `局部` | 本轮围绕真实问题做过页面/接口观察，但不等于完整 UAT |
| `否` | 尚未做系统性人工验收或多角色验收 |

## 2. 当前结论摘要

| 项目 | 结论 |
| --- | --- |
| 产品主轴 | 已具备“语言自学刷题系统”主链路，平台化与商业化能力也已存在，但成熟度不能只按“有代码”判断 |
| 当前最稳的链路 | 试卷详情、答题、答案/详解、基础进度与统计、题目反馈、章节式路径读取、登录上下文同步 |
| 当前最明显的不足 | 空模板卷仍进入试卷列表；题目级 `skill_tags` 仍为 `0 / 9080`；题库限时字段仍为 `0 / 88`；自动化覆盖仍偏编译/契约/仓储级 |
| 当前仍需重点治理 | 题库显式元数据、题目级 `skill_tags`、时间字段标准化、模板卷展示策略、平台能力的验收与测试补齐 |
| 本轮已确认通过 | 后端 Release 编译、前端 TypeScript 构建、`smoke_tests.exe`、`contract_v2_smoke.ps1`、`/api/v2/exams` `/api/v2/exams/{id}` `/api/v2/chapters` 冒烟 |
| 默认已收敛/隐藏 | 社区讨论、排行榜前台入口已隐藏；功能开关默认关闭 |

### 2.1 对这份文档本身的补充判断

- 当前文档更适合被理解为“能力盘点 + 可跑通程度”，不应直接等同“可对外稳定交付程度”。
- `smoke_tests` 与 `contract_v2_smoke` 已跑通，但前者主要覆盖 request id、推荐奖励、联系方式变更，后者主要覆盖 `exams` 与 `roles` 包络，不能替代试卷/答题/组织等业务回归。
- 多考试家族抽象、索引和前端运行时已经泛化，但本轮真实内容样本、接口冒烟与完成度判断仍几乎全部建立在 JLPT 数据上。

## 11. 文档结论

当前系统已经不是“只有刷题”的原型，而是一套：

- 自学刷题主链路已成型
- 平台/商业化能力已经存在
- 但对外可交付成熟度仍受模板卷展示、题目级知识标签、时间元数据和回归矩阵限制

如果接下来只做一件最值当的事，建议优先做：

`模板卷过滤 + 题目级 skill_tags + 主链路回归`

这三件事会同时提升：

- 首屏试卷选择体验
- 学习路径、推荐与错题诊断质量
- 多考试接入前的可交付可信度
