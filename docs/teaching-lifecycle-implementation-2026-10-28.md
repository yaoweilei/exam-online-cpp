# 教学交接与重复劳动改进 · 2026-10-28

## 已实现的业务入口

沿用班级详情的“课次”页，在原页增加“按周重复排课”“复制上一课”“人员变更”，展开后原页预览与确认，无需新增侧栏分类。作业布置页增加“复制本班上次作业”。

### N04 人员与教学关系变更

- 仅本机构管理员可以办理离班、同机构转班、教师/助教接任。先列出受影响课次、未完成作业、跟进与账户余额，再确认；确认需再次验证身份。
- 转班移出原班未来课次；原班该课次没有剩余学员时取消。是否加入目标班已排课由管理员明确选择，不勾选时预览明确提示不会加入既有课次。
- 换教师会检查接任职员的课程冲突。未完成的班级跟进转交接任人；学员转班有原班老师负责的未完跟进时，必须选择目标班有效负责人。
- 原班的未交/待重做作业、未结算课次先处理，避免成员离班后失去处理入口。原作业不自动复制到新班，也不自动替学员提交。
- 保留历史出勤、原任课人、扣课流水与补课关联。同机构的课时账户及余额不变。学员离班后仍能在“课程与课时”看到自己的原班课程与已交作业结果；老师可以继续补充批改，不能向已离班学员退回重做。
- 旧的直接停用/改写班级身份接口不能绕过交接。移除机构成员前，必须先处理活跃班级关系与未完跟进；移除授课身份前也会检查是否仍负责班级。
- 预览后班级/课次改变，提交返回冲突并要求重预览；重复请求不重复转班、转交或排课。有阻断项不部分保存。

这不是完整人事系统：跨机构转账/转班、学费退款、停用全站账号后的自动替代排班不在此流程中。紧急封禁账号仍属于独立安全操作，不因教学交接被阻止。

### N05 排课与作业复用

- 支持 1～52 节课，按本地日历间隔 1～12 周重复。逐节预览时间，并检查批次内部及已有师生排课冲突。
- 所有课次一起保存；任一课次无效/冲突，整批不保存。只生成排课，不默认完成考勤、不扣课。
- “复制上一课”沿用标题、时间间隔、授课名单和作业关联供重新核对；不复制出勤和扣课结果。
- “复制本班上次作业”只沿用标题与精确题目（包括不连续题目）。清除旧截止时间，不复制定向名单、催交、提交或批改记录。题目已变化时要求重新选题。

班级整体配置复制仍是后续扩展，没有把教师权限、学员名单或余额作为可直接复制的配置。

## 性能测量边界

在同一隔离机构、相同账号、同一机器中，单并发每个接口 5 次请求的中位耗时：工作台约 1,379 → 736 ms，班级课次约 1,492 → 357 ms，运营看板约 723 → 476 ms。证据：`tmp/teaching-lifecycle-20261028/read-baseline.json` 与 `read-optimized.json`。

这是包含大量历史测试账号的本地开发环境小样本测量，不是生产 SLA，不证明大班级并发或教学效果。未为测试修改本地 8080 的业务账号、成员或课时余额。

## 复验材料

代码与测试产物保存在 `tmp/teaching-lifecycle-20261028/`。主要用例为 `tests/e2e/teaching-lifecycle.spec.js`，覆盖原子保存、重复请求、冲突、权限、未完成事项、离班历史、评语与精确复制题目。截图检查包含 390 px 深色页面与失败后的输入保留。

真实试用验收仍待执行：机构管理员完成一次转班/换教师，教师安排一周课程并复制批改作业，学员完成原班历史查询和新班继续学习；记录独立完成率、耗时、误操作与中断点。学习效果比较使用此前未做过、目标与难度相近的材料，同时记录样本量；不得把重复原题的正确率提升直接当成迁移效果。
