## 检查范围与结论

- 覆盖 7 个角色的 47 个一级导航入口；逐页检查 **768×1024 竖屏、1024×768 横屏**。
- 补查用户详情、机构设置、成员编辑、课时分配、报价、校区、批改、结算、跟进、订单、资料、安全、消息、登录及答题等展开状态；选取价格、课程包和专项入口补查 820×1180、1180×820。
- 使用已有独立 8124 服务和数据副本，含 12 名学员、课程、作业、跟进、订单等记录；未在 8080 的真实数据上创建机构、修改价格或执行支付。
- 主入口没有检测到整页横向撑宽，但仍有**输入内容被裁切、重要操作在表格右侧不可直接看到、详情布局过密和多层表面嵌套**。不能仅凭 `scrollWidth` 正常判断 UI 合格。
- 覆盖 82 个场景、206 张索引截图。共确认 **16 项：1 项 P1、12 项 P2、3 项 P3**。P1 是影响金额核对的问题；P2 影响信息阅读、操作和触控；P3 是视觉规范与组织方式。T13 在最终实测中排除，编号保留以便追溯。

## 建议的实施顺序

1. **金额与关键操作**：T01、T02、T09、T11、T12。先保证完整金额、详情入口、保存操作和支付主按钮。
2. **机构页面减层级**：T03–T07、T16。复用已经认可的平铺列表、筛选、分页和白色表面；保留有用途的表格线。
3. **教学与学员触控**：T08、T10、T14。
4. **统一规范与登录**：T15、T17，最后复查横竖屏切换与桌面布局，避免为了平板改坏手机。

## 不需要一概重做的部分

- 用户管理的基本两行列表、机构详情概况、课程安排列表、出勤结算的逐人折叠、账号资料、安全和消息中心，当前横竖屏没有发现明显撑宽；主要延续共用样式即可。
- 教师只有一条备课、没有作业、只有一个学习组等短页面，底部留白由数据量造成，不必为了填满屏幕新增信息卡。
- 表格在自己的容器里横向滚动本身不算错误；审计页列入问题，是因为重要操作被藏住、可发现性差且行高异常。
- 宽屏显示侧栏、窄屏收起侧栏是合理行为，本轮不把断点切换本身列为缺陷。
- T13 专项练习数量入口在 CSS 局部声明中为 26px，但最终计算尺寸实际为 **48×44px**，已达到本轮触控建议，复核后排除，不列入待修改清单。不能根据单条 CSS 声明认定最终尺寸。[实测记录](verification.json)
- 阅读题的底部任务栏在初始画面覆盖部分下方内容，但滚动到底后四个选项与确认操作均可完整查看，本轮未将其认定为无法操作。[滚动后截图](screenshots/exam-reading-1024-scroll-end.png)
- 桌面内人工设成 820px 的预览额外采集在截图索引中，只作为容器适配探针，不等同于真实平板视口，也不据此认定独立产品缺陷。

## 验证边界

本轮为 Edge / Chromium 的 CSS 视口检查及 DOM 尺寸诊断，截图均可打开原图。结论主要针对布局，不宣称完成所有业务组合或真实平板测试。未播放整段音频、未执行真实支付、未保存价格；iPad Safari、触控手势、系统键盘、分屏与安全区仍需真机验证。答题场景使用专项文本、阅读、听力；旧的独立答题卡按钮已被任务导航替代，没有把其隐藏状态当成缺陷。
