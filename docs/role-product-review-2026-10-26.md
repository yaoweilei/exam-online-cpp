# 从机构经营、教学和学习任务检查当前产品

日期：2026-10-26。

初始 Review 范围：核对角色入口、首页任务、教学表单与机构服务实现，结合此前 7 角色、28 页的浏览器检查。下面保留初始问题与建议，实施结果、验证范围和业务边界见文末。

## 判断

系统已有较完整的个人练习能力，也有机构成员、学习组、作业、备课、排课、基础扣课和教学档案。下一步应围绕实际任务衔接这些能力：机构配置 → 学员入班 → 排课授课 → 作业反馈 → 学习跟进与课时续费。

当前的主要成本是：操作者需要记住多个功能入口、重复选择同一个班级或学员；部分列表虽有信息，却不能直接把事情处理到完成。视觉紧凑应继续保持，同时减少完成任务所需的步骤。

## 各角色应如何取舍

| 角色 | 可合并或降级 | 应补齐或改善 | 首页应该回答的问题 |
| --- | --- | --- | --- |
| 机构管理者 | 总览与机构看板减少重复；课程包模板与学员课时账户名称分清，互相关联；权限细项和审计放低频设置。 | 新机构配置进度；邀请/分班/分配老师的连续流程；近 7 天待办、教学履约、课时到期、待跟进；从汇总直接进入相同筛选的名单。 | 今天哪里需要我处理？目前教学和续课状况如何？ |
| 教师 | 课程表与安排课程归为“课程”；布置、未交、待批改归为“作业”的状态筛选；成绩册挂在班级及教学档案中。 | 今日授课卡直接进入班级，沿用本班上下文完成备课、课后作业和反馈；学生薄弱点可直接选题布置；常用评语、批改后下一份及修改留痕。 | 下一节教谁、教什么？哪些作业等我批？ |
| 教务 | 催交、异常、续费风险合入“学员跟进”的原因/状态筛选；课程表与排课复用同一工作区。 | 跟进负责人、期限、结果和历史；不同原因的提醒去重；排课冲突、改期通知与未处理名单；课时不足能进入正确账户。 | 今天该联系谁？哪些课程与课时需要协调？ |
| 学员 | 系统安排与自主练习保持清楚；复习相关入口集中；优惠邀请及购买入口维持账户区的低频层级。 | 全部老师任务入口；机构课程、余额和反馈；提交后明确已提交/待批改/待重做；个人自主学习与机构老师任务并列并说明优先级。 | 今天做什么？下次什么时候上课？老师反馈和剩余课时在哪里？ |
| 机构课程维护人员 | 当前机构内容管理只维护课程包，名称容易被理解为维护题库/教材；小机构无需为这一个功能额外切换身份。 | 对外可称“课程管理”，作为机构职员的一项授权能力；大机构仍可保留专职人员的受限工作台。 | 需要维护哪些课程规格？谁可以修改？ |
| 内容管理员 | 保留质量检查、解析审核、复核与发布的职责区别；常用功能维持当前页内切换，少做中转页。 | 从反馈定位到具体题目与版本，修改后回到待处理记录；记录处理结论；验证反馈者能获得结果。 | 哪些内容有问题？修到哪一步，由谁接着处理？ |
| 平台管理员 | 历史累计总数收为辅助；技术代码及高风险配置减少常驻；机构操作与平台操作范围清楚。 | 今日失败支付、服务异常、未处理反馈、发布阻断及超时任务等可操作名单；操作对象、机构和影响范围明确。 | 平台当前有什么故障和积压，下一步去哪处理？ |

同一角色从首页和侧栏进入同一个功能是有价值的，尤其窄屏菜单默认收起时。需要减少的是重复页面、重复选择对象和多个名称对应相同任务，而非简单删除首页入口。

## 推荐工作区结构

- 机构管理：概览 / 学员与员工 / 课程与课时 / 教学看板 / 设置。成员列表区分学员和职员，权限在职员详情中管理。
- 教师：今日教学 / 我的班级与学员 / 作业 / 备课。课程表内提供排课动作，班级详情内提供本班成绩。
- 教务：今日待办 / 学员跟进 / 课程安排 / 课时账户。提醒原因作为筛选，避免一名学员在多个页面重复处理。
- 学员：今日学习 / 我的课程（有机构关系时） / 自由练习 / 学习档案；目标在首页可调整，作业固定可达。

这里描述的是信息组织，实施时仍沿用已有白底、橙色选中态、紧凑概览、页内切换和统一消息入口。业务复杂的排课、批改、权限编辑可以保留专注的详情/编辑面板。

## 需要进一步确认的边界

1. 机构备注：当前教师备注写入学员全局档案，未携带机构 ID，读取也直接返回该档案的 teacher_notes。应专项验证同一学员同时属于两机构时的可见范围，并明确机构内部备注、任课教师备注、学员可见反馈的区别。这是当前代码结构提示的风险，未在本轮构造跨机构账号复现。
2. 排课冲突、重复扣课、改期通知、外部消息送达应以普通机构账号补做端到端验收；已有课程状态与基础扣课不能等同于这些复杂流程都已覆盖。
3. 平台会员订阅、机构购买平台席位、机构向学员收取学费是三类业务。当前平台订单及机构套餐账单不能直接当作机构学费财务台账。如果产品要覆盖机构收费，再设计报名订单、实收、退款及课时对应关系。

## 实施顺序

1. 先处理 C01/C02：让学员能发现全部任务，机构提醒符合真实业务含义，降低漏做与误报。
2. 归并教师课程和作业入口、教务跟进入口，统一机构/班级/学员上下文，保留筛选和返回位置。
3. 完成 C03/C04：批量入驻与跟进处理能持续推进到结束。
4. 补齐 C05/C07：班课课次、学员出勤、课时账目与学员查看构成完整授课流程，先明确扣课规则再实施。
5. 优化 C06 及机构看板，以相同目标下的学习变化和实际教学任务支撑判断。

暂不建议同时扩展完整招生 CRM、家长端、直播教室或更多独立工作台。若当前目标仍是考试学习与机构教学，先完成已有教学业务的连续使用路径，再按真实客户需求扩展。

配套调整：

- 教师课程表与排课合并，布置/待批改/未交/已完成归为“作业”；教务催交、风险和异常归为“学员跟进”，保留筛选与返回上下文。
- 机构运营页面沿用当前机构；机构首页增加成员、分班、课程课时、排课启用步骤。受限机构内容角色对外显示为“课程管理”，原角色和权限标识保留。
- 课程新增、改期、取消、完成和请假进入共用消息中心。学员打开自己的课程；任课教师/教务打开消息所属机构和班级的课次。
- 内容反馈增加“回复反馈者”，与内部处理备注分开；反馈者在消息中心获得处理结果，其他账号无法读取。
- 内部跟进按机构与授课关系隔离；不再把新备注写到学员全局档案。无机构归属的旧备注只向创建人保留可见，避免错误归入其他机构。
- 修复课程包编辑时后台刷新丢失未失焦输入的问题；短名称搜索不再偶然命中内部编号中间片段，编号支持完整值或前缀搜索。

### 扣课和兼容规则

- 出勤默认扣 1 次；缺席、请假和待补课默认不扣。教师逐人确认，可按机构规则调整为 0–10 的整数，结算前统一确认总数。
- 请假申请只表达申请，不直接替教师确认考勤或扣课。补课可只选择需要参加的学员。
- 已结算课次保留原始记录，不提供直接重写历史余额的入口。已有独立课次的班级不能再使用旧“一键完成学习组”重复扣课。
- 原有班级、课时账户和余额保留，不做推断性历史扣课迁移；新明细明确只记录逐课次结算。
- 跟进、课次、账目和课程通知增加到原机构存储结构中；不要求重建现有数据。
- 逐课次业务更新带存储版本保护；旧机构页面的整份保存若落后于新课次/跟进版本，返回冲突提示，避免覆盖已写入的课次和账目。

| 薄弱项直接布置 | 教师在学员详情选择该学员近期各卷错题，沿用班级和学员上下文布置定向作业。接收人、提交、班级作业列表、未交人数与催交均按指定学员过滤；同班其他学员不能查看或提交。 |
| 批改提效 | 我的常用评语按机构和创建人保存；可追加到当前学员评语、保存并进入下一份待批改提交、查看历次批改。后台刷新和保存失败保留未保存的评语与成绩。 |
| 机构启用向导 | 从成员/邀请与批量导入，进入分班、关联老师、可选分配课时，再在同一页安排首课。班级、授课关系和课时原子保存，重复提交不重复建班；有效同模板账户沿用，失效或耗尽账户不会被误当作可用账户。 |
| 教学运营看板 | 按日期和权限范围查看已排课、已完成、真实考勤、结束未结算、待确认请假及到期跟进，直接进入班级或学员档案；未结算课次不推断出勤率。 |
| 反馈修复闭环 | 新反馈关联服务端生成的版本快照与内容指纹，完成处理保存处理版本和历史；内容管理员可核对反馈时原题、打开当前原题，再通过固定返回入口回到原反馈和原筛选。旧反馈无快照时明确提示。中文反馈搜索、展开记录在后台刷新后丢失的问题一并修复。 |
| 平台操作待办 | 平台首页增加失败支付、跨日未完成订单/退款、发布阻断和跨日内容流程，可筛选并进入原业务详情。本机页面、存储、磁盘空间和数据读取检查单独展示；跨日待办不等于支付渠道故障。 |
