## 优先修复的实际问题

### UI-01 · P1 · 手机听力图片题显示不完整

**已复现。** 390px 下，N3 2010 年 7 月听力首题的四格衣服图片超出题目区域约 228px，右侧第 2、4 张图片不能完整看到。它们属于答题依据，这会影响选择答案。

建议图片默认适应当前可用宽度，保持比例；需要看细节时点开放大。恢复用户保存的拖拽宽度时，应限制在当前容器宽度内，窗口变窄后重新约束。不能仅隐藏横向滚动。

代码对应：`QuestionRenderer.ts` 恢复 `exam-image-width`；`image.css` 中普通容器限制为 `100%`，但 `.question-passage .exam-image-wrapper` 又将上限设成 `600px`，窄屏保护未覆盖这一组合。

**验收：** 图片题四个选项完整显示；390px、平板、横竖屏切换及保存过桌面拖拽宽度后均不裁切；放大可关闭并回到原题。

### UI-02 · P1 · 手机新建机构表单按钮越界

**已复现。** 展开“新建机构”后，机构名称和“创建”按钮仍占同一横排，按钮超出右边界；测得主内容横向溢出约 63px。普通机构列表没有同样的整页溢出，问题集中在创建表单。

建议手机将名称输入与创建按钮分成两行，按钮随容器宽度布局；创建动作放在必填字段之后。桌面仍可保留紧凑排版。

**验收：** 输入长机构名、打开软键盘和校验失败时，创建按钮及错误信息始终完整可见。

### UI-03 · P1 · 内容反馈搜索可能保留旧条件的结果

**已复现。** 在反馈列表切换每页条数后立即输入关键词搜索，若旧请求尚未完成，新查询会被加载状态拦截。输入框已经显示“读音题解析中的分段”，列表仍显示原来的 545 条总数和 20 行旧结果；同关键词接口实际返回 1 条。请求完成后再次搜索，才显示 1 条。这里的条数均来自隔离测试数据。

复现采用约 1.2 秒的读取响应延迟模拟慢网络，未修改反馈内容。证明记录见 [search-proof.json](D:/_develop/_side/exam-online-cpp/tmp/ui-full-audit-20261027/finish/search-proof.json)。

代码对应：`personalCenter.ts` 的 `loadFeedbackQueue()` 在 `platformFeedbackLoading` 为真时直接返回，没有保存待执行的新查询，也没有核对响应对应的查询条件。该组件由内容管理员及平台管理员复用。

建议以最新查询条件为准：记录请求序号/查询快照，忽略旧响应，或在旧请求结束后立即执行最后一次条件；加载时明确显示正在更新，搜索词、页码、每页条数与结果总数必须一致。

**验收：** 慢网络下连续搜索、筛选、翻页，最终显示最后一次条件的结果；零结果不残留旧行，失败后可以重试。

## 建议调整后的页面骨架

统一的是外框、密度和交互含义；不同任务需要不同的内部结构，不能把所有页面都做成同一套多层折叠。

| 页面类型 | 建议顺序 |
| --- | --- |
| 角色首页 | 标题与当前机构 → 一行概况 → 少量紧急待办 → 全部功能入口及选中的页内内容 |
| 列表页 | 标题与一个主要动作 → 简短搜索/常用筛选 → 列表 → 分页；批量动作只在选择后突出 |
| 班级详情 | 班级简要信息与下节课 → 课次/学员/作业/成绩切换 → 当前内容和就近操作 |
| 学员档案 | 姓名/目标/当前风险 → 学习表现/作业/跟进/课时切换 → 单个分析或表单 |
| 批改页 | 待批改数量与学员切换 → 作答与评分/评语 → 保存、下一份；提醒配置为次要入口 |
| 账号页 | 清楚的页面标题 → 基本资料或安全状态 → 分组设置 → 就地保存/反馈 |

保留所有角色首页的可达入口，尤其是窄屏侧栏默认收起时。移除的是重复内容与无用包裹层，不是把功能重新藏进菜单。点击页内功能时应保留标题、当前对象、筛选和滚动位置；确需离开当前操作时才进入详情。
